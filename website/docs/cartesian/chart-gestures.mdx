# Chart Gestures

Victory supports Gesture Handler 2 and 3 through the `Gesture` builder API, which is retained as the legacy API in v3. Use builder gestures for `customGestures` and external gesture relations; Gesture Handler 3's hook-based gestures cannot be composed with them.

The `CartesianChart` component has opt-in support for "press" gestures, including multi-press support. At this point in time, the "press" gesture support is limited to tracking the user's fingers' x-coordinate on the chart and exposing the _closest_ (in terms of x-coordinate) point to the user's gesture.

The goal for this press support is to allow the user to press/pan across the chart and track what x-value they're pressing/panning over.

## `useChartPressState`

At a high level, `useChartPressState` takes an initial state object and returns a `ChartPressState` value, which is effectively a wrapper around a group of Reanimated `SharedValue`s used to track the user's press gesture (and the corresponding x/y values and positions).

The signature for this function is:

```ts
useChartPressState<Init extends ChartPressStateInit>(init: Init): { isActive: boolean; state: ChartPressState<Init> }

type ChartPressStateInit = { x: InputFieldType; y: Record<string, number> };
export type ChartPressState<Init extends ChartPressStateInit> = {
  isActive: SharedValue<boolean>;
  x: { value: SharedValue<Init["x"]>; position: SharedValue<number> };
  y: Record<
    keyof Init["y"],
    { value: SharedValue<number>; position: SharedValue<number> }
  >;
};
```

You'll pass the `useChartPressState().state` value into the `chartPressState` prop of the `CartesianChart` component, and can use that `state` field to track e.g. active x-value or x-position of the users touch state. You can use the `useChartPressState().isActive` field to dynamically show elements with the user is actively pressing the chart.

## The `chartPressState` prop of `CartesianChart`

As outlined in [the Cartesian Chart page](./cartesian-chart.md#chartpressstate), the `chartPressState` prop of the `CartesianChart` component will accept a `ChartPressState` value returned from the `useChartPressState` hook and use that to track the users gesture state.

## Press gesture configuration

Use `chartPressConfig.pan` to pass configuration through to the underlying React Native Gesture Handler pan gesture. Explicit `0` values are applied, so values such as `activateAfterLongPress: 0` are valid.

When a chart is inside a scroll container, wrap React Native's `ScrollView` with a `Gesture.Native()` detector and pass that gesture through `simultaneousWithExternalGesture`. This works with Gesture Handler 2 and 3.

```tsx
import { useMemo } from "react";
import { ScrollView } from "react-native";
import { Gesture, GestureDetector } from "react-native-gesture-handler";
import { CartesianChart, useChartPressState } from "victory-native";

function ScrollableChart() {
  // Preserve the scroll recognizer across chart updates.
  const scrollGesture = useMemo(() => Gesture.Native(), []);
  const { state } = useChartPressState({ x: 0, y: { value: 0 } });

  return (
    <GestureDetector gesture={scrollGesture}>
      <ScrollView>
        <CartesianChart
          data={data}
          xKey="x"
          yKeys={["value"]}
          chartPressState={state}
          chartPressConfig={{
            pan: {
              simultaneousWithExternalGesture: scrollGesture,
            },
          }}
        >
          {/* ... */}
        </CartesianChart>
      </ScrollView>
    </GestureDetector>
  );
}
```

## Hover gesture support

The `CartesianChart` component (as well as `PolarChart` for pie/donut charts) supports tracking the user's mouse as it _hovers_ over the chart. On web, or on desktop builds, this lets readers explore a chart — e.g. read out values via a tooltip — without pressing anything. The hover gesture is built with the [`Gesture.Hover()`](https://docs.swmansion.com/react-native-gesture-handler/docs/gestures/hover-gesture) API from React Native Gesture Handler and is composed simultaneously with the press/transform gestures, so it never takes precedence over them.

Hover is aimed at pointer devices, so it is **enabled by default on web** — `enableHover` opts in on other platforms (and `enableHover={false}` opts out on web). Touch-only behavior is unchanged either way.

Press/click and hover interoperate: while the pointer is over the chart, pressing or clicking does not deactivate the hover-driven state — releasing the mouse button simply hands the tooltip back to the ongoing hover gesture — and moving the pointer out of the chart deactivates it as usual. On touch devices (where hover never activates), press behavior is exactly the same as it would be without hover.

### Hovering cartesian charts

Pass `enableHover` along with a `chartPressState` value: while the pointer is over the chart, the press state values are updated (and their `isActive` flags are set) exactly as if the user was pressing; when the pointer leaves the chart, the states are deactivated again. Because hover drives the press states themselves, no extra setup is needed to make hover match press.

```tsx
import * as React from "react";
import { View } from "react-native";
import { Line, CartesianChart, useChartPressState } from "victory-native";
import {
  Circle,
  DashPathEffect,
  Line as SkiaLine,
  vec,
} from "react-native-skia";
import { useDerivedValue, type SharedValue } from "react-native-reanimated";
import { AnimatedText } from "./components/AnimatedText";

const DATA = Array.from({ length: 31 }, (_, i) => ({
  day: i,
  highTmp: 40 + 30 * Math.random(),
}));

function HoverGestureScreen() {
  const { state, isActive } = useChartPressState({ x: 0, y: { highTmp: 0 } });

  const hoveredDay = useDerivedValue(() =>
    isActive ? `Day ${state.x.value.value}` : "Hover the chart!",
  );

  return (
    <View>
      <AnimatedText text={hoveredDay} defaultValue="Hover the chart!" />

      <CartesianChart
        data={DATA}
        xKey="day"
        yKeys={["highTmp"]}
        chartPressState={state}
        enableHover // 👈 activates the press state on mouse hover
        chartHoverConfig={{ activeCursor: "pointer" }}
        renderOutside={({ chartBounds }) =>
          isActive ? (
            <Cursor xPosition={state.x.position} chartBounds={chartBounds} />
          ) : null
        }
      >
        {({ points }) => (
          <>
            <Line points={points.highTmp} color="hotpink" strokeWidth={3} />
            {isActive && (
              <Circle
                cx={state.x.position}
                cy={state.y.highTmp.position}
                r={9}
                color="hotpink"
              />
            )}
          </>
        )}
      </CartesianChart>
    </View>
  );
}

function Cursor({
  xPosition,
  chartBounds,
}: {
  xPosition: SharedValue<number>;
  chartBounds: { top: number; bottom: number };
}) {
  const start = useDerivedValue(() => vec(xPosition.value, chartBounds.top));
  const end = useDerivedValue(() => vec(xPosition.value, chartBounds.bottom));

  return (
    <SkiaLine p1={start} p2={end} color="hotpink" strokeWidth={1}>
      <DashPathEffect intervals={[6, 4]} />
    </SkiaLine>
  );
}
```

### Distinct hover and press states

Sharing the press state keeps things simple, but hovering and pressing may need to be tracked independently — e.g. a hover tooltip that follows the mouse while a pressed tooltip stays pinned where the mouse last clicked. Pass a separate `chartHoverState` (a `ChartPressState` value created with `useChartPressState`, just like `chartPressState`) and the hover gesture will drive it instead of the press states:

```tsx
const press = useChartPressState({ x: 0, y: { highTmp: 0 } });
const hover = useChartPressState({ x: 0, y: { highTmp: 0 } });

<CartesianChart
  // ...
  chartPressState={press.state}
  chartHoverState={hover.state}
  enableHover // 👈 hovering now updates `hover`, pressing updates `press`
>
```

Each state (and its `isActive` shared value) is updated independently, so a "hover is active" readout and a "press is active" indicator can coexist.

Pie/donut charts (`PolarChart`) work differently: they always maintain a hovered-slice-index state, consumable inside chart content with the [`usePieHoverState`](/docs/polar/polar-chart#charthoverstate) hook; the [`chartHoverState`](/docs/polar/polar-chart#charthoverstate) prop only overrides it when the index needs to be read outside the chart.

## Multi-press support

The `CartesianChart` component can track as many fingers as you want, but two will likely be the max you'd reasonably want to use. See [the multi-press guide](./guides/multi-press.md) to see an example of multi-press in action.

To support multi-press gestures, you merely generate multiple `ChartPressState` values using the `useChartPressState` hook and pass those state values into the `chartPressState` prop as an array. For example:

```tsx
import { useChartPressState, CartesianChart } from "victory-native";

const INIT_STATE = { x: 0, y: { highTmp: 0 } } as const;

function MyChart() {
  // 👇 create multiple press states
  const { state: firstPress, isActive: isFirstPressActive } =
    useChartPressState(INIT_STATE);
  const { state: secondPress, isActive: isSecondPressActive } =
    useChartPressState(INIT_STATE);


  return (
    <CartesianChart
      // ...
      yKeys={["highTmp"]}
      // 👇 pass them both into chartPressState to be tracked
      chartPressState={[firstPress, secondPress]}
    >
      {() => (
        // ...
      )}
    </CartesianChart>
  )
}
```
